# Brand

treerig's visual identity: the mark, its small-size version, lockups, colour,
type and voice, and notes for wiring it into the project. For the illustrated
version, clone the repository and open [`brand-book.html`](brand-book.html) in
a browser: GitHub shows HTML files as source, not as a page.
[`decisions.md`](decisions.md) records how the name and the mark were chosen.

| | |
| --- | --- |
| Name | treerig, always lower case. Capitalise only to start a sentence. |
| Command | `treerig`. `trig` is a short alias, merged in #173; it ships with the first release (see [Integration](#integration)). |
| Line | A rig for every branch. |
| Mark | The Detached Fork. |
| Colour | Evergreen `#15271E`, Paper `#F3F5F1`, Signal Red `#C4362C` (`#F0715F` on dark). |
| Type | Archivo (display), IBM Plex Sans (body), IBM Plex Mono (code). |

The SVGs and the favicon PNGs are generated. Change the geometry or colours in
`source/build.py`, then run `python3 docs/brand/source/build.py`; don't hand-edit
them. The PNGs are palette images (transparent, ink, accent) with no metadata
and a stored deflate stream, so they are the same bytes on every machine. The
wordmark is stored in the script as outlines, so the font is not needed.

## The mark

The Detached Fork reads the way a worktree works:

- **The ring** is a commit on `main`, where the path starts.
- **The ink path** is `main`, running on to its next heading.
- **The red branch** is yours: the worktree you're in.
- **The gap** between the split and your branch is isolation. Your branch
  shares history with `main` and nothing else.

Construction, on a 64-unit grid:

- Paths are 6 units wide with round caps and joins.
- The commit ring has a 4.8-unit radius and a 4.4-unit stroke, with an open centre.
- The red branch starts clear of the split point. It never touches.
- Clear space is one ring diameter on every side.

Don't:

- Close the gap. The break is the meaning.
- Make both branches red. Red is only ever your branch.
- Rotate or mirror the mark. The path reads left to right.
- Scale the master below 20 px.

### Small sizes

At 16 px the master blurs: the ring fills in and the gap closes.
`treerig-favicon-16.svg` draws the same mark pixel by pixel. It has a 1 px
ring and arrowheads, doubled diagonal shafts, and one empty pixel kept at the
break.

- At 16 px, use the 16 px file.
- From 20 px up, use the master. The ring opens fully from 24 px.
- If a 20–24 px placement matters (some toolbars, the Windows taskbar), add a
  hand-tuned 24 px file the same way rather than scaling.

### Lockups and icon

The wordmark is Archivo ExtraBold at width 112, converted to outlines. The
mark sits on the baseline to the left of it. Don't re-set the wordmark in
another face, and don't move the mark to the right. The app icon is the dark
mark on an evergreen rounded square.

Evergreen and Paper carry nearly everything. Red is used sparingly and always
means one thing, yours; if it appears anywhere else it stops meaning that.
Text meets WCAG 2.1 AA (4.5:1) only in the pairings above. Ratios are computed
with the WCAG 2.1 relative-luminance formula.

State colours, for the CLI and the checkout index. They are proposed and not in
the code yet. They stay apart from Signal Red so that red keeps its one meaning.
Use the light column as a pill fill with white text, never as text on Paper. Use
the dark column as text or a marker on Night.

## Type

All three faces are on Google Fonts under the SIL Open Font License.

- **Archivo**, 800, width 112: headings and the wordmark.
- **IBM Plex Sans**, 400 and 600: body text.
- **IBM Plex Mono**, 400 and 500: code, commands, data.

## Use of the name and mark

The code is Apache-2.0, which grants no trademark rights (§6). Use of the name
and the mark by forks or packagers isn't covered here.

## Voice

Write the way the README already does: plain and exact, saying what happened,
what is guaranteed and what to do next. The name may play on rigs; help text,
errors and docs never do. In output, use the product's real nouns (worktree,
lock, home, container), and no puns, jokes or emoji. Output should read the
same in a CI log.

## Integration

Notes for wiring the identity into the project; each says whether it is done.

1. **README header** (done, #174). The `# treerig` heading is the lockup, so
   GitHub shows the dark version in dark mode:

   ```html
   <h1>
     <picture>
       <source media="(prefers-color-scheme: dark)" srcset="docs/brand/treerig-logo-dark.svg">
       <img alt="treerig" src="docs/brand/treerig-logo.svg" width="262" height="56">
     </picture>
   </h1>
   ```

   Give the `<img>` both `width` and `height` (262 × 56 is the lockup's
   aspect ratio), so the page doesn't shift as the image loads.

2. **Social preview.** Upload `treerig-social-preview.png` under the GitHub
   repository's Settings → General → Social preview. GitHub can't read it from
   the repository. The image shows `trig up`, which the alias (item 4)
   provides, so it can be uploaded. Not done yet.

3. **Checkout index favicon** (done, in the favicon pull request, #175). The
   index page, rendered by `internal/checkoutindex/render.go`, links six
   `<link rel="icon">` elements by relative path: the 32 × 32 and 16 × 16 PNGs
   (`sizes="32x32"`, `sizes="16x16"`) and the masters (`sizes="any"`), in that
   order. Each carries `media="(prefers-color-scheme: ...)"`, and in each pair
   the dark link comes first and the light one after it. Chrome and Edge
   honour `media` and match one link of the pair. Safari ignores `media` on
   icon links and takes the last match (observed in Safari on a light tab bar,
   where the earlier order showed the near-white dark icon), so it shows the
   light icon: right on a light tab bar, and a known limit on a dark one, since
   links give it no way to choose. Firefox most likely does the same (Mozilla
   bug 1603885, still open). `prefers-color-scheme`
   resolves to `light` or `dark` only (MDN: `light` also means no expressed
   preference), so no link without `media` is needed as a fallback. Chromium
   resolves the preference from the operating system, not the browser theme, so
   a dark tab strip on a light system gets the light icon, and links cannot fix
   that. The 16 px SVGs are not linked: they are pixel for pixel the 16 px
   PNGs. The PNGs come first because Safari
   before 26 ignores SVG favicons, and a `data:` one too (WebKit bug 236616),
   which is why the files are not embedded in the page.
   `Service.Refresh` and `Router.Ensure` write them beside `index.html` in the
   router's index directory (`checkoutindex.WriteIcons`, 0644, before the page,
   skipping a file that already matches), and the index container serves them
   with the types `image/png` and `image/svg+xml`. The page's
   Content-Security-Policy stays `img-src 'self'`. The files are copied byte for
   byte from `docs/brand` into `internal/checkoutindex/assets/`, and
   `TestFaviconsMatchBrand` in `internal/checkoutindex/favicon_test.go` fails
   when a copy differs from its file: after changing the mark, regenerate with
   `build.py`, then copy the files over. The same file's `TestFaviconLinks` pins
   the links, that each names a file `Refresh` writes, and the policy. No
   `apple-touch-icon` is offered: the page is served on the developer's own
   machine (`treerig.localhost` or a loopback port), so a phone's Home Screen
   never uses one. A second reason is that the app icon's curved strokes can't
   be rasterised exactly with the standard library alone. The index keeps its
   own neutral palette; adopting the brand colours there is optional.

4. **The `trig` alias** (done: merged in #173, ships with the first release).
   It was chosen during naming.
   `brand.CLIName` already follows the name the binary was invoked as, so the
   alias is only a second name on disk. How each install route provides it
   (Homebrew, `install.sh`, the Linux packages, the release archive, which
   carries no link, and the `trig` completions), and what each does when
   another `trig` is in the way, is recorded in
   [`docs/design/release.md`](../design/release.md), "The `trig` alias". The
   user-facing description is [The `trig` alias](../install.md#the-trig-alias)
   in the install docs.

   One-time check of other tools called `trig`, made in October 2026: an npm
   package `trig` from 2014 that installs a `trig` command, and a small Go
   helper for CodeKit (`zengabor/trig`). Neither is in Homebrew core or cask,
   Ubuntu, Nixpkgs or Scoop, and oh-my-zsh, Prezto and tldr-pages have no
   `trig`. Repeat the check if the alias is ever reconsidered.

5. **Domains.** `treerig.dev` and `treerig.com` had no DNS records when checked
   in October 2026. That suggests they were unregistered, but registration was
   not verified with a registrar.

6. **The previous-name guard.** `internal/style/branding_test.go` fails if
   any tracked file's path or contents carries the product's previous name in
   any letter case, binary files included. Keep it out of everything here,
   including the hand-made PNG.
