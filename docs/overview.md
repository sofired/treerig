# The overview

The overview is the machine-wide page at `http://treerig.localhost` (plus the
port, if changed). It lists every worktree on the machine across every project:
branch, hostname, directory, its [state](commands.md) (`running`, `partly
running`, `stopped`, `not started`, `directory missing`, …), and a link for each
service that opted in with `[service.<name>.index]`. A row that is `unknown`,
`removing` or `directory missing` says why, or what to run, beneath its state.
It is a static page served from the router stack, regenerated by `up`, `dev`,
`down`, `worktree rename` and `worktree remove`, and by `shared up` and `shared
down` when a routed shared UI changed — or by `treerig list --all --refresh`,
which also prints the table. Nothing else rewrites it; `treerig list` only
reads. The page says when it was generated. Beneath the worktrees it lists the
routed web UIs of the repositories' [shared services](shared-services.md) in a
group of their own. An open tab
fetches the page every 15 seconds and swaps the table in when the rows have
actually changed, advancing the timestamp quietly otherwise, so it follows along
without losing your place. It holds an update back while you are reading inside
a table with the keyboard, says so in the header when it has stopped being able
to read the page, and pauses on request. Without scripting it falls back to
reloading every 60 seconds.

The page's favicon is a set of six small files (PNG and SVG, light and dark),
the brand's favicon files (`docs/brand`), linked 32 px PNG, 16 px PNG, then
the master SVG, each as a dark link (`media="(prefers-color-scheme: dark)"`)
followed by a light one (`media="(prefers-color-scheme: light)"`). Chrome and
Edge match the one for their colour scheme. Safari ignores `media` and takes
the last match, so it shows the light icon, which is wrong on a dark tab bar
(a limit of the browser, not fixable with links); Firefox most likely does the
same. `Router.Ensure` (`up`, `router up`) and every refresh of the page write them
beside `index.html`, before the page, and the
same container serves them, so the page needs no more than `img-src 'self'`. A
write leaves a file alone when it already holds the right bytes. If one cannot
be written but an earlier copy is there, the page is still refreshed and a
warning names the file; with no copy there, the page is left as it was and the
refresh warns that the overview could not be refreshed. On a first write, `up` and
`router up` fail if an icon cannot be written, because the page would link a
missing file; on later refreshes a stale copy only produces a warning.

Each row's state is told by the same code `status` and `list` use, from the
registrations, one `docker ps` per label namespace and Git's worktree list. Git
is asked about every repository that has a worktree, eight at a time and all
within five seconds together: the one the command that refreshed the page ran
in, and any other through a directory one of its worktrees last ran from, which
must still belong to that repository. A repository
whose recorded directories are all gone is judged by those directories alone,
and one Git does not answer for shows its rows as `unknown`, with the cause.
The [state words](commands.md) say what each means and when a directory counts
as missing. When Docker cannot be asked, every row that needs it reads
`unknown` and the page says so in a notice; a row whose directory is missing or
whose removal is under way is still shown as that.

`treerig list --all` prints the same rows as a table, with the worktree's
directory and the URL of its first service that loads, and `treerig list --all
--json` has everything the page is built from, with the state as
`entries[].state` ([Machine-readable output](json-output.md)). Neither needs a
`treerig.toml`, and without `--refresh` neither writes anything. `treerig
index`, which printed the page as text, is gone: it prints a pointer to `list
--all` and exits 1, for one release. On a terminal, inside a repository,
`treerig list` ends with the page's address when the router serves this root's
URLs; with `--all` it does not, since it already lists everything.
