# Checkout index

The machine-wide page at `http://treerig.localhost` that lists every checkout.

`http://treerig.localhost` (plus the port, if changed) lists every
checkout on the machine across every project: branch, hostname, path, whether
its services are running, and a link for each service that opted in with
`[service.<name>.index]`. It is a static page served from the router stack,
regenerated by `up`, `dev`, `down`, `worktree rename` and `worktree remove`,
and by `shared up` and `shared down` when a routed shared UI changed — or by
`treerig index`, which also prints it as text. Beneath the checkouts it lists the
routed web UIs of the repositories' [shared services](shared-services.md) in a
group of their own. An open tab fetches the page every 15 seconds and swaps the
table in when the rows have actually changed, advancing the
timestamp quietly otherwise, so it follows along without losing your place. It
holds an update back while you are reading inside a table with the keyboard,
says so in the header when it has stopped being able to read the page, and
pauses on request. Without scripting it falls back to reloading every 60
seconds.

The page's favicon is a set of six small files (PNG and SVG, light and dark),
the brand's favicon files (`docs/brand`), linked 32 px PNG, 16 px PNG, then
the master SVG, each as a dark link (`media="(prefers-color-scheme: dark)"`)
followed by a light one (`media="(prefers-color-scheme: light)"`). Chrome and
Edge match the one for their colour scheme. Safari ignores `media` and takes
the last match, so it shows the light icon, which is wrong on a dark tab bar
(a limit of the browser, not fixable with links); Firefox most likely does the
same. `Router.Ensure` (`up`, `router up`) and every index refresh write them
beside `index.html`, before the page, and the
same container serves them, so the page needs no more than `img-src 'self'`. A
write leaves a file alone when it already holds the right bytes. If one cannot
be written but an earlier copy is there, the page is still refreshed and a
warning names the file; with no copy there, the page is left as it was and the
refresh warns that the index could not be refreshed. On a first write, `up` and
`router up` fail if an icon cannot be written, because the page would link a
missing file; on later refreshes a stale copy only produces a warning.

`index` needs a `treerig.toml` — the nearest one above the working directory,
or the one `--config <path>` names — even though what it prints spans the
machine, as does every verb that starts, stops or inspects a project. Three
verbs and the completion of worktree names read only labels and records, and
work without one: `worktree list` (see [Running without a treerig.toml](worktrees.md#running-without-a-treerigtoml)),
`worktree unlock` and `worktree remove <worktree>`. `router` works without
one too.
